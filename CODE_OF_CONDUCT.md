# Code of Conduct

## Scope

This applies to issues, pull requests, discussions and any other space where the project is
represented.

## Expected behaviour

- Critique the artifact, not the person. "This severity table is wrong because X" is
  welcome; "you clearly don't understand CTI" is not.
- State your confidence and your evidence. The project's whole argument is that a claim
  without either is not intelligence; the same applies to a code review.
- Accept correction. Being wrong about an attribution, a TLP rule or a STIX constraint is
  normal; insisting after the evidence is shown is not.

## Not acceptable

Harassment, personal attacks, discriminatory language, publishing someone's private
information, and using the project's artifacts to target or expose real people or
organisations without a lawful basis.

## Enforcement

Report a problem to the maintainer at the address in [`SECURITY.md`](SECURITY.md). Reports
are handled privately. Consequences range from a request to stop, to removal from the
project's spaces.

## Attribution

This is a short project-specific code of conduct, not the Contributor Covenant. If the
project grows beyond a single maintainer, it should adopt one.
